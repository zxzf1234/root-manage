# Codex 使用建议

## 文档说明

本文档面向刚开始使用 Codex 的研发人员。

---

## 提问技巧

### 1. 指定明确的文件范围

不要这样提问：

```text
帮我看看这个项目有什么问题
```

建议：

```text
只看以下文件：

frontend/src/components/Table.vue
frontend/src/hooks/useContextMenu.ts

目标：
将右键菜单逻辑抽离。

不要修改其他文件。
```

原因：

* Codex 会主动搜索项目内容
* 搜索范围越大，Token 消耗越高
* 范围越明确，结果越准确

推荐模板：

```text
涉及文件：

目标：

限制条件：

不要修改：
```

---

### 2. 大任务先分析方案

不要直接说：

```text
帮我重构整个模块
```

建议：

```text
先不要改代码。

请分析：

1. 需要修改哪些文件
2. 每个文件修改什么内容
3. 存在哪些风险

确认后再开始修改。
```

适用于：

* 模块重构
* 架构调整
* 大型功能开发
* 跨模块修改

优点：

* 降低错误修改风险
* 减少返工
* 节省 Token

---

### 3. 选择合适的 Reasoning Level

不同任务使用不同思考深度。

#### Low

适合：

* CSS 修改
* 文案调整
* SQL 修改
* 配置修改
* 简单 CRUD

特点：

* 响应最快
* Token 最省

---

#### Medium

适合：

* Vue 页面开发
* Spring Boot 接口开发
* 普通功能开发
* 常规 Bug 修复

推荐作为默认选择。

---

#### High

适合：

* 复杂 Bug 排查
* 大型重构
* 性能优化
* 多模块联动开发

仅在必要时使用。

---

## 会话管理

### 4. 避免要求全量重写文件

不要：

```text
重写整个文件
```

建议：

```text
只修改 xxx 函数

保持原有结构

不要修改其他逻辑
```

或者：

```text
只输出需要修改的代码片段
```

原因：

* 大文件会消耗更多 Token
* 更容易引入无关修改
* 更容易产生换行符问题

---

### 5. 一个任务一个会话

不要在同一个会话中持续累积大量任务。

推荐：

#### 会话 A

```text
修复登录问题
```

完成后结束会话。

#### 会话 B

```text
优化列表页面
```

重新开始新会话。

#### 会话 C

```text
新增导出功能
```

重新开始新会话。

原因：

* 历史上下文会不断累积
* Token 消耗越来越高
* 长会话更容易出现上下文污染

---

### 6. 使用固定提问模板

推荐统一使用：

```text
目标：

涉及文件：

背景：

限制条件：

不要做：

完成标准：
```

示例：

```text
目标：
抽离右键菜单逻辑

涉及文件：
frontend/src/components/Table.vue

背景：
当前右键菜单逻辑全部写在 Table.vue 中

限制条件：
不修改现有功能

不要做：
不要修改表格渲染逻辑

完成标准：
右键菜单迁移到 useContextMenu.ts
```

优点：

* Codex 理解更快
* Token 更省
* 跑偏概率更低

## 推荐实践

### 简单问题

推荐：

```text
Reasoning：Low
```

适用于：

* CSS
* SQL
* 配置
* 文案

---

### 普通开发

推荐：

```text
Reasoning：Medium
```

适用于：

* Vue 开发
* Java 开发
* 接口联调
* 常规 Bug

---

### 复杂任务

推荐：

```text
第一步：
先分析方案

第二步：
确认方案

第三步：
再开始编码
```

适用于：

* 架构调整
* 大型重构
* 性能优化

---

## 推荐提问示例

### 示例一：修复 Bug

```text
目标：
修复商品列表分页失效问题

涉及文件：
GoodsController.java
GoodsService.java

限制条件：
不要修改接口返回结构

完成标准：
分页正常生效
```

---

### 示例二：功能开发

```text
目标：
新增商品导出功能

涉及文件：
商品模块相关文件

要求：
先分析需要修改哪些文件
确认后再开始编码

不要做：
不要修改现有导入功能
```

---

### 示例三：代码重构

```text
目标：
抽离右键菜单逻辑

涉及文件：
Table.vue

要求：
先给出重构方案

不要直接修改代码
```

---

## 总结

为了获得更好的 Codex 使用体验，建议遵循以下原则：

1. 明确指定文件范围
2. 大任务先分析方案
3. 根据任务选择合适的 Reasoning Level
4. 避免全量重写文件
5. 一个任务一个会话
6. 使用固定提问模板

在实际开发中，仅遵循以上几点，通常就能显著降低 Token 消耗，并提高代码生成质量与任务完成效率。
